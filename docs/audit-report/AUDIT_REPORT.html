Security Concerns & Recommendations

⚠️ Cron Job Security: Cron endpoints rely on CRON_SECRET header validation. Ensure this token is:
  • Cryptographically strong (minimum 32 characters)
  • Rotated periodically
  • Never exposed in public repositories
  • Monitored for unauthorized access attempts
⚠️ Token Caching: Coral SSO token endpoint uses 5-minute stale-while-revalidate cache. Monitor for token replay attacks in production.

Key Observations & Risks

🔴 Multiple Supabase Projects: Three separate projects (shop, live/membership) increases operational complexity:
  • Separate credentials to manage (6 environment variables)
  • Separate billing tiers for each project
  • Database migrations must be coordinated across projects
  • Cross-project queries require federation (not ideal)
⚠️ View Tracking Privacy Concern: Raw IPs stored temporarily before hashing:
  • Edge function must run reliably (cron failure → IP accumulation)
  • Consider immediate hashing on view insertion instead of async processing
  • Current model: IPs visible to service role until batch job runs
⚠️ Download Counter Atomicity: Migration atomic_download_counter suggests previous race conditions. Verify counter logic is protected.
⚠️ Unused RLS Policies: Review 20260430000003_rls_service_role_documentation.sql for potential unused/redundant policies.
✓ Geolocation Ready: Schema includes city, state_province, country fields. Geolocation can be added to batch job without schema changes.
